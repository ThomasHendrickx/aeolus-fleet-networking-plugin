# The networking plugin: architecture

`@aeolus-fleet/networking-plugin`: a long-running Node process, hosted beside squadrons, serving every fleet of the server with one connection each and switched per fleet as squadrons is (decisions [0021](https://github.com/ThomasHendrickx/aeolus-fleet/blob/main/docs/decisions/0021-squadrons-installation.md), [0036](decisions/0036-networking-plugin-package.md)). It reaches each fleet only through the public API, as that fleet's networking plugin ship (`fleet:read`, `fleet:network`), and is the fleet's one networking plugin (decision [0035](https://github.com/ThomasHendrickx/aeolus-fleet/blob/main/docs/decisions/0035-networking-plugin.md)). Its own small database holds per fleet the connection (its ship and kept crew token), the switch and the network argo edits: the rules, the whole list or none, and what it declares for while it is unavailable. The fleet keeps only the list it last supplied: argo's rules with the rules the fleet's ships declared added, which it reads from the fleet and supplies again when it follows a NetworkRulesDeclared (decision [0037](https://github.com/ThomasHendrickx/aeolus-fleet/blob/main/docs/decisions/0037-declared-network-rules.md)). It depends on `common` only.

What lives in core: the product and its language in aeolus-fleet's [blueprint](https://github.com/ThomasHendrickx/aeolus-fleet/blob/main/docs/blueprint.md), the network rules and their limits in decision [0034](https://github.com/ThomasHendrickx/aeolus-fleet/blob/main/docs/decisions/0034-network-rules.md), and the calls this package makes and the minimum core version it checks in [docs/compatibility.md](https://github.com/ThomasHendrickx/aeolus-fleet/blob/main/docs/compatibility.md).

| Layer | Pieces |
| --- | --- |
| Core (pure) | **Supply**: per fleet, register with argo's declaration (or `keep-latest` after 300 seconds) and set the whole list where it is on; unregister where it is off. **Supplies**: one supply of a fleet at a time, a refused one kept for the next retry, in memory (a start supplies every fleet anew). **Network**: read it, save the rules within decision 0034's limits, save the declaration, each supplied at once. **Receive**: acknowledge every delivery to its ship, a ping with pong. **Connection**, **installation** and **operator**, as the trierarch plugin's, a delete unregistering first |
| Ports | **FleetDoor**: the ship calls it makes as its ship (register, whoami, fleet.ship, the networking plugin calls, receive, ack). **ConnectionStore**, **FleetSwitches**, **FleetNetworks**, **InstallationRequests**, **ConsoleSessions**, **Clock** |
| Adapters | REST to the fleet; tRPC for the web app's server (`connection`, `network`, `installation`); Prisma on its own database (`connections`, `fleet_switches`, `fleet_networks`, `installation_requests`); a receive loop per fleet it serves and is connected to; a timer that retries refused supplies |

## Deployment

A long-running Node process beside squadrons, with a small Postgres database of its own holding each fleet's connection, switch and network (it may share squadrons' Postgres server, in its own schema), on any VM or container host next to the server. It needs no public address: only the web app's server and the fleet's API talk to it or it to them.
